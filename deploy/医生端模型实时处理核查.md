# 医生端预约模型分析核查报告

## 结论

医生端已按请求实时编码共享贴文，FeaLearner 实时统计词性，Emocc 实时处理逐帖生成的 emoji。两条分支均使用 Weibo 分类器。核查通过了特征结构和部分本机组件测试，训练数值等价性和生产预约报告仍待验证。

## 从预约到报告

`DoctorRiskDesk.execute` 调用 `POST /api/care/appointments/{id}/review`。`CareController.review` 校验医生、已接受预约及快照版本，按快照顺序取前 32 条共享贴文。检测类别在接口中统一叫 `emocc`，后台按 `modelId` 解析实际模型家族。`PostReviewService.review` 将文本发往 `/infer/appointment-review`，返回报告前控制器再次核对快照。

| 环节 | 实现依据 | 核查结果 |
|---|---|---|
| 两模型文本预编码 | `appointment_review.py` 的 `encode_posts`、`bert_models` | 本地 `CARE_BERT_DIR` 提供 tokenizer 和 BERT。每批最多 8 帖，每帖截断到 128 token，取最后一层首 token 向量，形成 `[1, 帖数, 768]`。只检查隐藏维度，两个模型共用同一编码器。训练时生成向量的权重版本、分词、截断、池化仍需逐模型核对。 |
| FeaLearner 词性统计 | `appointment_fealearner.py` 的 `feature_row` | 文本清洗后用 `jieba.posseg` 分词标注。先匹配完整词性，再尝试前两位和首位，累计 57 类计数，除以有效贴文数。分母是帖子数，非总词数。全部清洗为空会失败。 |
| FeaLearner 特征融合 | 同文件的 `resources`、`classifier`、`review` | 拼接 57 维词性、50 维冻结 TF-IDF、10 维 NRC、13 维加权词典，共 130 维。列组顺序与 `feature_weibo_2.csv` 表头一致。文本向量和这 130 维一起进入分类器。`export_weibo_tfidf.py` 含导出时的训练表对照，但不能替代对当前实时函数全部 130 列的逐值验证。 |
| Emocc 表情处理 | `RiskService.appointmentEmojis`、`appointment_review.py` 的 `emoji_features`、微博训练 `BertEmojiDataset` | Java 将每条贴文发送给配置的表情模型（默认 `qwen-flash`），要求生成 3–5 个 emoji。Python 按可见字符簇校验，再按 Unicode 码点取前 10 个，查微博词表并生成 mask，未知码点使用 `<UNK>`。码点编码、截断及 mask 与训练加载器一致。训练加载器允许缺失序列，医生接口对空串或不合规响应会失败。若需求是提取作者原帖自带的表情，当前实现不符合该项。 |
| 医生报告 | `PostReviewService.review`、`RiskService.enrichPostDetection`、`DoctorRiskDesk` | 服务验证检测器名称、风险等级与分值范围，再调用外部模型解释检测结果。报告提示限制重新评分，正文预览最多 15 帖、每帖 80 字。只有返回 `llm_analysis` 且前端取得摘要等有效字段，页面才显示完成。报告模型失败，即使本地分类成功，医生也会看到任务失败。 |

## 实际验证与边界

- 本机以两条合成中文贴文实际调用 `feature_row`，得到有限值张量 `[1,130]`。配合 `[1,2,768]` 的零向量检查输入契约，仓库 FeaLearner 权重成功前向，返回 `[1,2]`。零向量只用于验证接口和维度。
- 本机加载 Emocc 权重与微博训练词表，两者均为 45 项。向一条帖子提供三个单码点 emoji，得到 `[1,1,10]` 的 ID 张量和 3 个有效位置。词表从 CSV 重建，只比较长度无法识别同长度的 ID 排列变化。
- 本机未配置 `CARE_BERT_DIR`，且当前 Transformers 与 huggingface-hub 版本不兼容。此次没有在本机用真实训练编码器取得完整报告。此前生产直连侧车的 Emocc 样例成功，FeaLearner 返回通用 503。该响应也覆盖缺词典、导入错误、特征值错误等情况，无法仅据此确定根因。直连侧车绕过了 Java 生成 emoji 和撰写报告两个环节。

## 上线验收依据

1. 在可信环境选取能与离线训练记录准确对应的样本，对照同一组贴文和顺序，分别记录两模型的编码器版本、向量形状及数值误差。FeaLearner 逐组比较 POS、TF-IDF、NRC 和加权词典。Emocc 固定同一组 emoji，比较逐项 ID、mask 和分类输出。只记录误差与版本。
2. 在已授权的测试预约使用合成贴文，从医生页面分别执行两个模型。核对报告对应的模型、快照、输入条数与风险等级，并确认摘要成功显示。报告中按类别映射的风险分数应作为模型输出解释，不能作为个体临床概率。
3. 失败时按表情生成、本地文本编码、手工特征、分类权重和报告生成分别定位。FeaLearner 当前缺少 Emocc 已返回的 `inferenceBackend` 字段，验收应结合服务端模型执行结果。
